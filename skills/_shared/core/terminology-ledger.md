# Terminology ledger (discipline defaults)

Canonical, discipline-standard terms so prose stays internally consistent. This
is the **base** layer; the user's *project* profile supplies a project-specific
glossary (its own coined terms, abbreviations, notation) that **layers on top**
and wins where it is more specific. Never mix variant spellings of the same
concept within a manuscript.

## Use consistently

- **functional connectivity (FC)** — not "functional correlation", "functional
  link". Define the abbreviation on first use, then use it.
- **structural connectivity (SC)** — not "anatomical connectivity" mid-paper if
  you opened with SC.
- **resting-state fMRI (rs-fMRI)**, **region of interest (ROI)**,
  **gray matter (GM)** / **white matter (WM)**.
- **parcellation / atlas / nodes** — pick one word per concept and keep it.
- **cohort / dataset / sample** — do not drift between them for the same group.

## Abbreviation hygiene

- Define every abbreviation at first use; do not redefine it later.
- Do not abbreviate a term used only once or twice.
- The project profile's abbreviation list is authoritative for coined terms
  (e.g. a model name, a bespoke metric). If the project profile is absent, keep
  a running list as you draft and reuse it.

## Notation

- Notation (symbols, subscripts) is a *project* concern — take it from the
  project profile's notation glossary and match it exactly across Methods,
  equations, figures, and captions. Do not introduce a symbol the project
  profile does not define.

## Cohort naming

- Name public cohorts by their standard acronym (e.g. ADNI, OASIS, HCP-Aging)
  and state the release/subset once; do not switch between the acronym and a
  paraphrase.
